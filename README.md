# LeadSort — ИИ-разбор входящих заявок

Сервис принимает заявки с сайта, из Telegram и почты, а нейросеть раскладывает их по полочкам: тип, срочность, контакты, бюджет и сроки, вопросы клиенту и черновик ответа. Менеджер видит заявки на канбан-доске, о срочных узнаёт в Telegram.

**Демо-легенда:** веб-студия «Пиксель».

> Проект в разработке. Готовы сайт студии с формой (`/pixel`), канбан-доска (`/app`), песочница разбора одной заявки (`/try`) и демо-набор из 25 заявок; статистика и Telegram-бот — следующие этапы.

## Сайт студии с формой

`/pixel` — сайт вымышленной веб-студии «Пиксель»: услуги и цены, этапы работы и форма заявки. Форма отвечает сразу, разбор идёт в фоне, а рядом панель «Что увидел менеджер» показывает путь заявки: получена → разобрана нейросетью → на доске, с замером времени. Обычно заявка оказывается на доске разобранной через 3–7 секунд после отправки.

Кнопка «Отправить тестовую заявку» заполняет форму случайным примером — новый сайт, доработка, поломка, вопрос, спам или «только телефон» — и отправляет её. Имя, город, бюджет и телефон каждый раз разные, поэтому разбор идёт через нейросеть, а не из кеша.

## Доска заявок

- Колонки «Новая → В работе → Ждём клиента → Закрыта» и свёрнутая колонка «Спам». Карточки перетаскиваются мышью, на телефоне — долгим нажатием.
- Спам уходит в свою колонку сам, его можно вернуть кнопкой «Не спам». Перенос в «Спам» и обратно меняет тип заявки.
- Фильтры по типу, срочности и каналу, поиск по тексту, имени и контактам.
- Карточка заявки: исходный текст с подсветкой найденных контактов рядом с тем, что извлекла нейросеть. Любое поле правится вручную и помечается «изменено»; «Разобрать заново» возвращает свежий разбор. У каждой заявки есть история: получена, разобрана, перенесена, поправлена.
- «Добавить заявку» — вставить текст письма. Заявка сохраняется сразу, разбор идёт в фоне, карточка обновляется сама.
- Регистрации нет: у каждого посетителя своя копия демо-доски (анонимный id в `localStorage`). «Сбросить демо» возвращает исходные 25 заявок, доски без визитов дольше суток удаляет ночная очистка.

## Как устроен разбор

```
Текст заявки ─► правила: пустое сообщение? только контакт? ─► готово без нейросети
                      │
                      ▼
               LLMProvider ─► JSON по схеме ─► Pydantic
                      │
     контакты сверяются с исходным текстом: выдуманный телефон в карточку не попадёт
                      │
                      ▼
          тип, срочность, контакты, бюджет, сроки, вопросы, черновик ответа
```

- Телефоны, почта и ники Telegram ищутся регулярками в любом виде записи: `8 (916) 123-45-67`, `+79161234567`, `anna [at] mail.ru`, `olga собака gmail точка com`, `t.me/username`. Номера договоров, ИНН и цены телефоном не считаются.
- Слой `LLMProvider` (`backend/app/llm/`) выбирается переменной `LLM_PROVIDER`: `openai` — любой OpenAI-совместимый API, `yandex` — YandexGPT, `mock` — разбор по ключевым словам без внешнего API.
- Спам и пустые сообщения никогда не вызывают уведомление.
- Одинаковые тексты берутся из кеша Redis, число разборов ограничено по IP.

## Демо-заявки и точность

В `backend/app/seed/pixel-leads.json` — 25 заявок студии «Пиксель» разного качества: подробные брифы, сообщения капслоком без знаков препинания, контакты вперемешку, письмо на английском, резюме соискателя, взлом сайта с «рекламой казино», SEO-рассылки, бессмыслица и пустая форма. У каждой заявки записан правильный ответ: тип, срочность и контакты.

Скрипт прогоняет их через нейросеть, сверяет результат и сохраняет разборы в `pixel-leads.results.json` — демо-доска берёт их оттуда, поэтому первый визит не тратит токены:

```bash
cd backend
uv run python scripts/evaluate_demo.py --report demo-report.html
```

Последний прогон на gpt-5.6-luna: **тип верно в 25 из 25** заявок (цель — 22), все телефоны, адреса и ники найдены в 25 из 25, срочность совпала в 24 из 25. Тест `test_contacts_found_without_model` проверяет, что контакты из всех 25 заявок находятся и без нейросети.

## Запуск локально

Нужен Docker.

```bash
cp .env.example .env
docker compose up --build
```

- Сайт студии с формой: http://localhost:3000/pixel
- Доска: http://localhost:3000/app
- Песочница разбора: http://localhost:3000/try
- API и Swagger: http://localhost:8000/docs

По умолчанию `LLM_PROVIDER=mock` — всё работает без ключей. Чтобы подключить настоящую модель, укажите в `.env`:

```env
LLM_PROVIDER=openai
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-5.6-luna
OPENAI_REASONING_EFFORT=none
```

### Тесты

```bash
cd backend
uv sync
uv run pytest
uv run ruff check app tests
```
